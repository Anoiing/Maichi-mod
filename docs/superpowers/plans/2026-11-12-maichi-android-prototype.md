# 麦驰室内机安卓直连原型开发方案与计划

第一版在安卓平板上实现本户的主动监控和呼叫电梯。用现有抓包开发并验收离线原型，配件到手后通过家里 Wi-Fi 的无线 ADB 安装、调试，再验证对讲网有线接入。门口来电、接听、挂断和双向对讲排在补抓包之后。

## 开发方案

### 应用与接线

采用原生 Kotlin 单模块 App，用 Android View 和 XML 布局。首页与监控页共用同一套协议和会话逻辑。开发阶段由本地抓包样本驱动，真机联调时改用安卓有线网口收发 UDP。

- 平板的 USB-C 接带 RJ45 和 PD 输入的扩展坞，墙内对讲网线接 RJ45，平板充电器接 PD 输入。
- Mac 和平板在家里 Wi-Fi 上配对无线 ADB。配件到手后实测插网线时 Wi-Fi 和调试是否保持连接。若平板切断 Wi-Fi，先装调试包，接有线复现后恢复 Wi-Fi 读取日志。 [Android 真机和无线调试](https://developer.android.com/studio/run/device)
- App 通过 `ConnectivityManager` 获取以太网 `Network` 和 `LinkProperties`，使用 `Network.bindSocket()` 把 UDP 套接字绑定到有线网络，分别在本机 `10008` 和 `10000` 端口收发。选择接口时以可用的有线 IPv4 为依据，适配仅能访问楼宇局域网的链路。 [Android Network.bindSocket](https://developer.android.com/reference/android/net/Network#bindSocket(java.net.DatagramSocket))
- 实机使用本户可接入的终端地址和身份，本地配置保存室内机和门口机标识。示例样本使用本机 `192.0.2.10/24` 和对端 `192.0.2.20`。正式切换时先让原机离线，确认平板的静态 IPv4、前缀和本户终端绑定。

### 抓包依据与实现边界

| 能力 | 已观察到的行为与实现方式 |
| --- | --- |
| 设备发现 | 本机 UDP `10008` 向有线子网广播地址发送 35 字节查询。广播地址由本机 IPv4 和前缀计算。查询首字节 `0x01`，紧跟门口机标识。回应首字节 `0x02`，其余字节一致。按已配置的门口机标识匹配回应并取得对端 IP。 |
| 主动监控 | UDP `10000` 使用 `PENGUIN0` 包头和 `b8 00` 标记。先发带 `VIDEOA` 的 172 字节 `0x0001`，约 1 秒后还有同类型的 80 字节包。另一次入站样本在视频前出现 `0x0003`（92 字节）和 `0x0002`（80 字节）。出画期间双方都发 `0x000c`，退出附近都有 `0x001e`。原型参考 RJ3 中 `0x000c` 的约 110 毫秒中位间隔，实际触发条件和节奏在同次双向抓包中校准。 |
| 监控媒体 | `0x000a` 为媒体包，偏移 80 起依次读取媒体类型、帧号、分片总数、分片序号和有效长度，每项为 16 位小端无符号整数。偏移 90 起是内容。类型 `1` 按分片序号拼 JPEG，收到完整帧后交给 Android 解码。已离线验证 608 帧和另一份 168 帧，均为 640 × 480。类型 `3` 暂识别并统计音频块，按约 8 kHz 单声道 PCM 的推断留待有声样本验证。第一版以监控画面为验收项。 |
| 本户呼梯 | 复用设备发现，向对端 UDP `10000` 发送 `06 01`、`0x0001`。`rj3-ev.pcapng` 第 3 包的实际载荷为 74 字节，偏移 14 的小端长度字段为 32，偏移 32 起为本户室内机标识和填充。序列化按 74 字节生成。`1111111.pcapng` 第 1353 包的 32 字节 `0x0002` 是应答候选。等待同一对端回应时允许一个呼梯请求在途，超时给出提示，重试由用户点按触发。到梯结果按现场观察记录。 |

`PENGUIN0` 消息由偏移 8–9 的标记、偏移 10–11 的小端类型和实际载荷长度共同识别。监控报文的固定身份区由室内机标识、室内机 IPv4、门口机标识和门口机 IPv4 组成，分别位于偏移 32、52、56 和 76。标识为 20 字节字段，末尾补零，IPv4 按 4 字节网络序写入。视频入站和出站样本来自两次操作，离线模拟按上述观测构造对端，真机阶段再验证每个回应对应的请求。

### 平板界面

参考原麦驰横屏首页，以 HUAWEI MatePad 11（DBY-W09，2560 × 1600）为主要适配目标，手机用于兼容性调试。顶部居中显示暖金色时钟，左侧显示日期，右侧显示 `离线样本` 或对讲网连接状态。中间横向排列「监控」「电梯」和「设置」三个功能块，设置块提供本户参数和音量入口。中文和时钟使用系统字体，文字与间距按 dp、sp 及平板资源配置适配，内容区域限制最大宽度。

| 用途 | 颜色 |
| --- | --- |
| 底色 | `#151619` |
| 面板底色 | `#222429` |
| 分隔线 | `#3B3E43` |
| 时钟与操作强调色 | `#F0C795` |
| 深底文字 | `#F4F1EB` |

```text
┌──────────────────────────────────────────┐
│ 11/12 周四            20:30       离线样本 │
│ ┌────────────┬─────────────┬────────────┐ │
│ │    监控     │     电梯     │    设置    │ │
│ │            │ 等待设备回应  │ 连接与音量  │ │
│ └────────────┴─────────────┴────────────┘ │
└──────────────────────────────────────────┘
```

- 监控入口先进入门机选择页，用三个横向平铺的功能块展示单元门机和两台待接入的地库门机，选择页采用蓝色系。单元门机预览用黑底画布按 4:3 原比例显示画面。返回按钮和连接状态持续可见，等待、出画、断开及超时均有状态提示。退出或离开前台时结束会话并释放画面缓存。
- 设置页逐项展示本机和对端参数，通过编辑弹窗修改，连接方式通过右上角按钮打开弹窗。平板使用双列面板，宽度小于 600dp 的窗口使用单列。界面跟随系统方向，重建时恢复所在页面、字段草稿、选择范围、校验提示和待保存的连接方式。媒体与通话音量分别调整，即时生效。
- 电梯格在点按后显示 `等待设备回应`，收到匹配回包显示 `已收到设备回应`，超时显示 `未确认，请重试`。离线回包显示 `模拟回应`。
- 来电功能到后续版本时加入对讲入口和来电页。首版首页仅展示可用功能。

## 实施计划

### 1. 建立工程和样本

- [x] 使用 Temurin JDK 17、Gradle Wrapper 9.1.0、Android Gradle Plugin 9.0.1 内置 Kotlin 和 Android SDK 36 创建 `:app`。原型暂定 `minSdk 26`、`compileSdk 36`、`targetSdk 36`，联调前核对平板实际版本。Mac 已检测到 JDK 17 和 Gradle 9.1.0，开发前配置 SDK Platform 36、Build Tools 36.0.0、Platform Tools 和适配本机架构的安卓模拟器。 [AGP 9.0.1 兼容表](https://developer.android.com/build/releases/agp-9-0-0-release-notes)
- [x] 实现 `tools/export_capture.py --input-dir DIR --output-dir DIR`，调用本机 TShark 提取本户 UDP 数据，导出相对时间、方向、本机端口、对端 IPv4 和端口、载荷。使用 `video.pcapng` 和 `rj4.pcapng` 验证视频入站，使用 `rj3.pcapng` 和 `rj3-ev.pcapng` 比对发送，使用 `1111111.pcapng` 验证应答解析。样本放在 Git 忽略的 `.maichi-fixtures/`。调试 APK 只打包回放使用的两份样本，放在 `app/src/debug/assets/maichi-local/`。设备标识用示例值。
- [x] 运行 `./gradlew :app:assembleDebug`，得到可安装的调试 APK。

### 2. 实现协议和画面重组

Kotlin 文件放在 `app/src/main/kotlin/com/maichimod/prototype/`。同包的 JVM 测试放在 `app/src/test/kotlin/`。

| 文件 | 职责 |
| --- | --- |
| `protocol/MaichiPackets.kt` | `encodeDiscovery(peerId)`、`encodeMonitor(command, profile, peerIp)`、`encodeElevator(indoorId)` 生成 UDP 载荷，`decode(localPort, payload)` 识别控制包或媒体分片。 |
| `protocol/JpegAssembler.kt` | `accept(fragment, nowMs, decode)` 在分片齐全且解码成功时返回画面。按当前会话和帧号合并，过滤重复和越界分片，清理超时的半帧。解码失败时继续等待有效画面，并保留出画超时。 |
| `session/TerminalSession.kt` | 提供 `openMonitor()`、`closeMonitor()`、`callElevator()`，统一管理对端、等待状态和定时任务。退出监控或切换传输方式时清理旧会话。 |
| `transport/DatagramTransport.kt` | 为会话提供同一组收发方法。接收记录包含来源 IP、来源端口、本机端口和载荷。 |

- [x] 在 `MaichiPacketsTest.kt` 中用样本核验设备查询、监控开始与退出、74 字节呼梯和 32 字节回包。断言呼梯实际载荷为 74、偏移 14 的长度字段为 32、室内机标识从偏移 32 开始。覆盖短包和异常长度。
- [x] 在 `JpegAssemblerTest.kt` 中验证有效长度和分片序号。用真实样本比对完整帧数，用测试样本验证乱序、重复和缺片，确保丢一帧后下一帧还能正常显示。
- [x] 在 `TerminalSessionTest.kt` 中模拟发现超时、监控退出后晚到的分片、非匹配对端的回应、呼梯连点与超时。验收每次有效点按只发送一次呼梯请求，退出后停止监控的周期包。离线原型从 2 秒发现等待、5 秒出画等待和 3 秒呼梯回应等待起步，现场按实际时序调整。
- [x] 运行 `./gradlew :app:testDebugUnitTest`，并对本地 `video.pcapng` 导出的样本核验 608 帧 JPEG。确认呼梯生成的字节与第 3 包匹配，测试环境使用示例终端标识。

### 3. 交付可操作的离线 App

- [x] 在调试构建加入 `transport/FixtureTransport.kt`。在会话发出查询和控制包后，由样本对端回送相应的应答和媒体分片。首屏可直接演示监控、退出、呼梯和超时状态。
- [x] 在 `MainActivity.kt` 和 `app/src/main/res/layout/` 实现参考图的首页和监控页。在后台解码 JPEG，界面绘制最新完整帧。记录操作时间、方向、报文类型、长度和超时，供 `adb logcat` 排查。
- [x] 加入 `transport/EthernetTransport.kt` 和本户配置。使用以太网 `Network` 分别绑定两个 UDP 套接字，根据有线 IPv4 和前缀计算广播地址。断开时释放套接字并提示状态，恢复后可重新发起操作。原型使用 `INTERNET` 和 `ACCESS_NETWORK_STATE`。将来若升到目标 API 37，再接入对应的局域网权限。 [Android 局域网权限](https://developer.android.com/privacy-and-security/local-network-permission)

- [x] 在 Android 36 平板模拟器验证横屏与竖屏的布局、字段校验、音量、系统返回和弹窗重建恢复，并通过故障注入验证坏帧、断线、收发异常、重连和旧任务取消。小米 6 已安装启动最新版本，当前自动界面检查受 MIUI 限制。平板实机接网验证进入下一阶段。

### 4. 配件到手后无线 ADB 联调

- [ ] 在家用网络验证扩展坞充电、有线收发，以及插网线后的无线 ADB。查看平板以太网设置是否支持静态 IPv4 和本户实际前缀。用无线 ADB 安装调试 APK 并查看日志。
- [ ] 在本户的实际对讲网接入时先让原机离线。由 App 的状态和抓包确认 `10008` 查询和 `10000` 控制包走有线，且对端正确回应。
- [ ] **先验监控。** 点击监控，确认发现对端、稳定出画、退出后停止流量。复测拔插网线后的重连。比对同次收发，校准 80 字节短包和 `0x000c` 的触发及间隔。
- [ ] **再验呼梯。** 正常按一次本户呼梯，记录请求、`0x0002` 回包以及电梯是否到达。在同一次操作里核对三者。联调结束若恢复原机，切回本户原机的接线和身份配置。

补到门口机呼叫本户、接听、两端说话和挂断的抓包后，再扩展现有会话和媒体逻辑，验收锁屏来电与双向语音。整机撤除以平板独立完成这些场景、监控、呼梯和断网恢复为准。
