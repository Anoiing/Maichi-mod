# 专用门禁终端验收记录

本记录区分本地自动测试、隔离模拟器与真实门禁现场结果。未执行不等于通过。禁止用自动测试触发真实开锁或呼梯。

## 环境与阶段

- 开发基线：`c65ddbe`；方案基线：`547d807`。
- 本地：JDK 17，Android target 36，离线回放使用本机私有样本。
- 隔离模拟器：API 31、API 36，独立任务/配置测试，不连接真实门机。
- 现场平板：DBY-W09 / API 31；2026-11-13 只读检查时 USB 供电、电量 100%。此读数不证明网口与持续供电同时可用。
- 2026-11-14 调试构建已完成目标平板离线与实际重启检查，并开始真实门禁网络验证，安装包及证据见当日记录；现场来电、双向声音、物理门锁、电梯、网络拔插及有线开机恢复仍待完成。旧包前台来电失败已记录在后文。
- 24 小时 / 72 小时观察尚未开始；第一期现场验收通过之前不接入相机感知。

## 执行规则

每次记录构建提交、设备/API、步骤、预期、实际、时间和必要证据。模拟器不验证厂商保活/锁屏限制或物理设备效果。系统授权/系统设置由现场人员参与；强行停止后需手动打开应用，这是系统行为。

失败先修复并重跑相关路径，再进入下一阶段。任何配置、主题、页面或自动返回的变化，都要核对没有额外创建/关闭监听 Socket。

新增现场故障报告（旧安装包，前台来电尚未复测）：用户确认单元门呼叫时门禁 App 正在前台，门机立即显示通话结束，平板无反应。后续只读检查时屏幕已经 Asleep，UDP 10008/10000 均未监听，无接待 Service；旧包未包含 IntercomService/IncomingCallActivity/StartupReceiver。这只能确认旧包存在息屏/后台停止接待的独立问题，不能解释用户确认的前台故障。

### 地址根因与持久化阻断

系统 `IEthernetManager.getConfiguration("eth0")` 实际返回 `IP assignment: UNASSIGNED`，网口仍由 DHCP 管理，门禁地址只是内核中的附加地址。针对系统持久配置的实时断言先失败，当前地址可用不代表重启能够保留。

在备份原系统配置并核对应用参数不变、三台门机及已存网关可达后，尝试通过系统以太网配置服务保存本户静态配置。系统以 `SecurityException` 拒绝，明确要求 `android.permission.NETWORK_STACK` 或 `android.permission.MAINLINE_NETWORK_STACK`；实际权限声明为系统签名级。异常由一次性配置工具的进程产生，门禁接待进程和网口配置保持原状。复读仍为 `UNASSIGNED`，因此持久化没有修复，不进行尚无持久配置依据的重启验收。

本机系统设置的完整 Manifest、代码符号和资源中，未找到静态以太网配置入口；系统 `ethernet` / `network_stack` 无可用配置命令，`connectivity` 命令仅提供飞行模式操作。原应用的普通权限和操作检测授权不能提供系统网络栈权限。

华为提供 `DeviceNetworkManager.setEthernetConfiguration`，要求设备管理激活及 `MDM_NETWORK_MANAGER` 权限；本机该权限为签名/特权级。官方新项目授权途径涉及企业资质、HEM 集成和设备 License，不能将启用普通设备管理器等同于已经授权。是否存在可用的华为管理授权，或可由用户管理的有线网络 DHCP 配置，已向用户核实；在途径明确前不增加无法执行的 App 网络配置代码。
