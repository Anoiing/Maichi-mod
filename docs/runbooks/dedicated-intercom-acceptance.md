# 专用门禁终端验收记录

本记录区分本地自动测试、隔离模拟器与真实门禁现场结果。未执行不等于通过。禁止用自动测试触发真实开锁或呼梯。

## 环境与阶段

- 开发基线：`c65ddbe`；方案基线：`547d807`。
- 本地：JDK 17，Android target 36，离线回放使用本机私有样本。
- 隔离模拟器：API 31、API 36，独立任务/配置测试，不连接真实门机。
- 现场平板：DBY-W09 / API 31；2026-11-13 只读检查时 USB 供电、电量 100%。此读数不证明网口与持续供电同时可用。
- 现场真实来电、双向声音、物理门锁、电梯、网络拔插、重启和闲置返回尚未执行。
- 24 小时 / 72 小时观察尚未开始；第一期现场验收通过之前不接入相机感知。

## 执行规则

每次记录构建提交、设备/API、步骤、预期、实际、时间和必要证据。模拟器不验证厂商保活/锁屏限制或物理设备效果。系统授权/系统设置由现场人员参与；强行停止后需手动打开应用，这是系统行为。

失败先修复并重跑相关路径，再进入下一阶段。任何配置、主题、页面或自动返回的变化，都要核对没有额外创建/关闭监听 Socket。

阶段 4：68 项 JVM、9 项 Python、API 31/API 36 各 49 项完整设备测试通过；Debug 构建和 Lint 通过，仍只有工具链新版提示。三轮复审，最后两轮均无本阶段待修复发现。

- 临时 I/O 错误持续按 0.5、1、2、5、10、30 秒退避，之后 30 秒；绑定成功不清零，合法对端报文或持续监听 60 秒清零。虚拟时钟还覆盖旧 Socket 失败回调晚到、无网卡不空转、等待地址 10 秒说明，以及权限错误停止重试。实际设置 TextView 验证恢复说明与通知授权提示能同时展示。
- 一个 CPU 部分唤醒锁，非引用计数，每次限 10 分钟、每 60 秒核查和续期；有效网口监听/绑定/重试或活动通话需要持有，无网口、配置/权限阻塞或停用释放。设备用例使用真实 Service 和真实 WakeLock，未用离线资源预载替代保活核查。
- 来电/监控/呼梯的相对时间包含睡眠；收到报文、执行命令与界面重新绑定前核查截止时间。先到的自动挂断与超时按原期限处理；过期接听、开锁和迟到呼梯回应不再生效。开锁执行源直接给出三态结果，明确未发送不会误报发送不确定。重复手动重试去重，旧停用状态不覆盖新启动。
- API 31 隔离模拟器实际设置测试 PIN 后重启，系统为 RUNNING_LOCKED 时接待服务已在前台；正常输入 PIN 后为 RUNNING_UNLOCKED，同一进程、同一次演示资源加载，临时 PIN 已清除。仅接待类型为 connectedDevice，不恢复旧通话、录音或控制操作。
- API 31 经设置停用后重启，服务未自动启动。API 36 强行停止后没有服务，待系统强停标志落盘再重启仍为 stopped=true；用户显式重新打开可恢复。最初立即 ADB 重启会丢失尚未持久化的系统强停标志，已区分为测试前置条件，未为此添加应用规避逻辑；系统包限制的延迟持久化见 [AOSP PackageManagerService](https://android.googlesource.com/platform/frameworks/base/+/master/services/core/java/com/android/server/pm/PackageManagerService.java)。应用接待开关使用自身同步持久化，不依赖这项系统延迟。

上述实际重启仅发生在隔离模拟器。物理平板、真实网口/IP 恢复、双向声音、门锁、电梯、厂商后台策略及 24/72 小时验收仍未执行。


新增现场故障报告（旧安装包，前台来电尚未复测）：用户确认单元门呼叫时门禁 App 正在前台，门机立即显示通话结束，平板无反应。后续只读检查时屏幕已经 Asleep，UDP 10008/10000 均未监听，无接待 Service；旧包未包含 IntercomService/IncomingCallActivity/StartupReceiver。这只能确认旧包存在息屏/后台停止接待的独立问题，不能解释用户确认的前台故障。

进一步核对实际安装包的传输代码及系统路由：网口同时配置家庭网和门禁网 IPv4，旧包 UDP 10008 绑定通配地址，回复未指定门禁源地址；系统对门机的路由查询实际选用家庭网源地址。已用真实 UDP Socket 在 API 31/36 隔离模拟器复现：回复来自主地址而非配置地址。现修改为同一传输实例持有通配发现接收端、固定门禁地址的发现收发端和原会话端，保留广播接收并固定发现回复源地址。未放宽来源或身份校验。

该修复经过两轮复审，无待修复发现；78 项 JVM、9 项 Python、Debug 构建/Lint 通过。API 31/36 各 15 项针对性设备回归通过，包含实际子网广播只交付一次、两条接收路径、回复源地址、部分绑定失败/正常关闭释放资源、恢复和来电操作。错误源地址可能导致门机在正式来电前结束握手，这是依据现有证据的推断；真实故障是否因此解决仍待后续现场呼叫。按用户要求未安装到平板，未更改现场配置、网络或系统授权，未发起接听、开锁或呼梯。
