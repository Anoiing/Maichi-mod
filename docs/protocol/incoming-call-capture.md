# 单元门来电抓包与原型

`mmmmm11111111.pcapng` 是门机返回方向，`mmmmmm2222222.pcapng` 是室内机发送方向。这两份记录来自分别重复的两次操作，均包含两阶段来电；不能直接对齐两份文件的时间轴。此前 `44444.pcapng` 只有返回方向，可作为来电视频、身份区和结束消息的补充证据。

## 操作对应

室内机请求记录的第一阶段是接听、短通话、挂断。第二阶段在 42.024 秒发送接听消息，43.157 秒开始发送语音，45.589 秒才出现仅此阶段具有的类型 `6` 消息，49.137 秒挂断。用户确认这一次可能先接听再开锁，因此按实际报文顺序分析。类型 `6` 与开锁对应的证据较强，真实开门结果仍以现场观察为准。

返回方向完整解码得到第一阶段 339 帧、第二阶段 331 帧 JPEG，全部为 640 × 480；对应语音为 293 和 273 个有效块。请求方向有 273 和 187 个上行语音块。

## 握手与控制

所有长度均为 UDP 载荷长度，整数采用小端。除设备发现外，消息以 `PENGUIN0` 开头，偏移 8 为家族、10 为类型、14 为声明长度。

| 方向 / 用途 | 格式 | 原型处理 |
| --- | --- | --- |
| 门机查询本户 | UDP `10008`，35 字节，`01` 后跟本户 `S` 标识 | 只响应本户查询，向来源地址返回同长度的 `02` 应答。 |
| 门机查询室内机列表 | UDP `10000`，`98 00`、类型 `1`，32 字节 | 校验配置的对端地址，或此前短窗口内有效的本户查询。 |
| 室内机列表回应 | `98 00`、类型 `2`，898 字节 | 偏移 32 为数量 `1`，34 为本户标识，54 为本机 IPv4，其他位置补零。 |
| 门机发起来电 | `b7 00`、类型 `1`，256 字节，80 起为 `VIDEOA` | 校验来源、门机标识、本户标识和本机地址后进入响铃。重复请求不自动接听。 |
| 室内机协商 | `b7 00`、类型 `3`，96 字节 | 尾部为 `VIDEOA 00 00 32 00 09 00 09 00 ff 00`。 |
| 接听 | `b7 00`、类型 `5`，80 字节 | 由本次来电的接听按钮发送一次。 |
| 开锁请求 | `b7 00`、类型 `6`，80 字节 | 只在用户点按时发送，不自动重试。原报文本身不结束视频；App 可按设置在 3 秒后另发结束消息。尚未验证独立的成功回包。 |
| 保活 | `b7 00`、类型 `12`，80 字节 | 参考室内机记录约 110 毫秒间隔。 |
| 结束 | `b7 00`、类型 `30`，80 字节 | 处理对端结束；本机挂断时发送一次，取消本次任务。 |

`b7` 身份区与主动监控 `b8` 的顺序相反：门机标识在 32、门机 IPv4 在 52、室内机标识在 56、室内机 IPv4 在 76。两个会话使用各自的解码与身份验证。

## 视频与语音

类型 `10` 的媒体元数据从偏移 80 起依次为类型、帧号、分片总数、分片序号、有效长度，均为 16 位；内容从偏移 90 开始。类型 `1` 为 JPEG 分片，按完整帧解码后显示。类型 `3` 的有效内容为 512 字节。

语音字节分布符合小端 16 位 PCM，结合连续块的时间与总字节数，推断为 8 kHz 单声道。原型使用此格式播放，接听后启用同格式的麦克风上行，并参考样本在接听后约 1.1 秒开始。尚未完成真机听音、双向可懂度、回声和长期延迟验收。

结束后出现的 `9b` 文件名和 `b4` 图片分片属于另一组文件传输消息，未作为开锁回应，也未实现该文件传输功能。

## 已完成的回归与边界

本地归一化样本保存 4,191 条入站和 645 条出站消息。入站测试逐帧解码 670 帧 JPEG、校验 566 个语音块；出站测试逐条比对发现回应、列表回应、协商、接听、开锁、保活、结束及语音包头。原始标识、地址、视频和声音只保存在忽略的本地文件和调试构建中，正式构建不带样本。

会话测试覆盖本户筛选、手动接听、关闭自动挂断时保留视频、挂断后晚到数据、超时、发送失败和超过 30 秒仍保持的来电。新增 3 秒自动挂断、重复开锁重置计时、手动模式取消计时、发送失败及旧计时不能影响下一通的验证。界面操作和麦克风权限结果绑定本次来电标识，避免上一通的按钮或权限结果作用于下一通。

当前原型只在 App 前台接收来电；后台、锁屏唤醒和进程长期保活尚未实现。离开前台、挂断或断线会停止声音和麦克风。离线演示不录音、不向楼宇网络发送数据。连续 8 秒无匹配数据时结束来电；主动监控独立使用 30 秒上限。

## 现场验收

系统以太网配置和 App 本户参数就绪后，依次验证单元门来电出画、接听后双方说话、挂断停止流量，再分别验证接听前与接听后的手动开锁。开锁必须由现场人员观察门锁结果，不能仅依靠“请求已发送”的提示判定成功。最后补测连续来电、来电打断监控、拔插网线、离开前台和恢复连接。
