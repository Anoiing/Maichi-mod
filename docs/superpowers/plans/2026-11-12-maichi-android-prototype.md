# 麦驰室内机安卓直连原型开发方案与计划

本计划从主动监控和呼叫电梯的离线原型起步，经无线 ADB 和对讲网有线联调，现已加入补抓包支持的前台来电、接听、挂断、开锁和语音原型。下文实施步骤保留各阶段记录；当前界面以[平板界面记录](2026-11-13-tablet-visual-redesign.md)为准，真实来电、双向声音与物理开锁仍待现场验收。

## 开发方案

### 应用与接线

采用原生 Kotlin 单模块 App，用 Android View 和 XML 布局。首页与监控页共用同一套协议和会话逻辑。开发阶段由本地抓包样本驱动，真机联调时改用安卓有线网口收发 UDP。

- 平板的 USB-C 接带 RJ45 和 PD 输入的扩展坞，墙内对讲网线接 RJ45，平板充电器接 PD 输入。
- Mac 和平板在家里 Wi-Fi 上配对无线 ADB。配件到手后实测插网线时 Wi-Fi 和调试是否保持连接。若平板切断 Wi-Fi，先装调试包，接有线复现后恢复 Wi-Fi 读取日志。 [Android 真机和无线调试](https://developer.android.com/studio/run/device)
- App 通过 `ConnectivityManager` 获取以太网 `Network` 和 `LinkProperties`，使用 `Network.bindSocket()` 把 UDP 套接字绑定到有线网络，分别在本机 `10008` 和 `10000` 端口收发。选择接口时以可用的有线 IPv4 为依据，适配仅能访问楼宇局域网的链路。 [Android Network.bindSocket](https://developer.android.com/reference/android/net/Network#bindSocket(java.net.DatagramSocket))
- 实机使用本户可接入的终端地址和身份，本地配置保存室内机和门口机标识。示例样本使用本机 `192.0.2.10/24` 和对端 `192.0.2.20`。正式切换时先让原机离线，确认平板的静态 IPv4、前缀和本户终端绑定。

### 抓包依据与实现边界

| 能力 | 已观察到的行为与实现方式 |
| --- | --- |
| 设备发现 | 本机 UDP `10008` 向有线子网广播地址发送 35 字节查询。广播地址由本机 IPv4 和前缀计算。查询首字节 `0x01`，紧跟门口机标识。回应首字节 `0x02`，其余字节一致。按已配置的门口机标识匹配回应并取得对端 IP。 |
| 主动监控 | UDP `10000` 使用 `PENGUIN0` 包头和 `b8 00` 标记。先发带 `VIDEOA` 的 172 字节 `0x0001`，约 1 秒后还有同类型的 80 字节包。另一次入站样本在视频前出现 `0x0003`（92 字节）和 `0x0002`（80 字节）。出画期间双方都发 `0x000c`，退出附近都有 `0x001e`。原型参考 RJ3 中 `0x000c` 的约 110 毫秒中位间隔，实际触发条件和节奏在同次双向抓包中校准。 |
| 监控媒体 | `0x000a` 为媒体包，偏移 80 起依次读取媒体类型、帧号、分片总数、分片序号和有效长度，每项为 16 位小端无符号整数。偏移 90 起是内容。类型 `1` 按分片序号拼 JPEG，收到完整帧后交给 Android 解码。已离线验证 608 帧和另一份 168 帧，均为 640 × 480。类型 `3` 暂识别并统计音频块，按约 8 kHz 单声道 PCM 的推断留待有声样本验证。第一版以监控画面为验收项。 |
| 本户呼梯 | 复用设备发现，向对端 UDP `10000` 发送 `06 01`、`0x0001`。`rj3-ev.pcapng` 第 3 包的实际载荷为 74 字节，偏移 14 的小端长度字段为 32，偏移 32 起为本户室内机标识和填充。序列化按 74 字节生成。`1111111.pcapng` 第 1353 包的 32 字节 `0x0002` 是应答候选。等待同一对端回应时允许一个呼梯请求在途，超时给出提示，重试由用户点按触发。到梯结果按现场观察记录。 |

`PENGUIN0` 消息由偏移 8–9 的标记、偏移 10–11 的小端类型和实际载荷长度共同识别。监控报文的固定身份区由室内机标识、室内机 IPv4、门口机标识和门口机 IPv4 组成，分别位于偏移 32、52、56 和 76。标识为 20 字节字段，末尾补零，IPv4 按 4 字节网络序写入。视频入站和出站样本来自两次操作，离线模拟按上述观测构造对端，真机阶段再验证每个回应对应的请求。

### 平板界面

以 HUAWEI MatePad 11（DBY-W09，2560 × 1600、密度 400）为主，手机仅调试。按用户最新要求严格对齐 Mediora 当前前端规范及原始令牌，映射表和用户覆盖项见[样式对齐记录](2026-11-13-tablet-visual-redesign.md)。

- 工作区 #FFFFFF、正文 #262626、结构线 #E5E5E5、主操作 #A3E635，正常连接采用 #DCFFF1 / #7EE2B8。
- 页面标题 32sp / 600，普通卡片与分区标题 20sp，正文 16sp，辅助信息 14sp；来电操作文字 20sp。平板时间 88sp bold，日期与星期均为 32sp bold。
- 普通控件 4dp、卡片和弹窗 8dp、白色工作区 20dp 圆角；控件 Ink 细边框、结构 Rule 细分隔。页头为左标题、右操作、下方 Ink 线。
- 用户指定所有卡片和按钮保留硬阴影，覆盖规范的无阴影默认；触屏默认 2dp、按下 1dp，没有 hover。禁用保持独立颜色和不可操作，处理中保留颜色并去阴影。
- 首页上排为主题色米家与监控入口，下排为电梯与设置。米家主卡配低对比圆弧装饰，背景使用轻量光束与流星；旧黑金 Founder 卡面已被替代。卡片与监控入口图标为 48dp 双色填面，紧凑操作沿用 Lucide 圆头线形；网络状态为 32dp 纯展示图标，不可点击。
- 监控选择保留单元门、地库 1 和地库 2 三块横向入口。图像按原始 4:3 显示，主动查看最长 30 秒，结束后回到选择页。
- 来电左视频、右两个大正方形操作；开锁为次级按钮，接听为当前主题色主按钮，接听后切为红色语义的挂断。按钮随可用高度等比缩放。
- 设置分为本机与网络、门机设备、声音与通话、外观；采用开放双列表单，窄窗口或大字体单列。数值平时以纯文字展示，逐项编辑与校验；音量即时生效，连接方式使用弹窗。单选有圆形标记，开关按 32×20 / 16 / 2dp 令牌绘制，全局主题有九种配色。
- “开锁后自动挂断”默认开启，成功发出请求后 3 秒结束来电，关闭则手动挂断。重复开锁重置计时，结束或断线取消。

### 2. 实现协议和画面重组

Kotlin 文件放在 `app/src/main/kotlin/com/maichimod/prototype/`。同包的 JVM 测试放在 `app/src/test/kotlin/`。

| 文件 | 职责 |
| --- | --- |
| `protocol/MaichiPackets.kt` | `encodeDiscovery(peerId)`、`encodeMonitor(command, profile, peerIp)`、`encodeElevator(indoorId)` 生成 UDP 载荷，`decode(localPort, payload)` 识别控制包或媒体分片。 |
| `protocol/JpegAssembler.kt` | `accept(fragment, nowMs, decode)` 在分片齐全且解码成功时返回画面。按当前会话和帧号合并，过滤重复和越界分片，清理超时的半帧。解码失败时继续等待有效画面，并保留出画超时。 |
| `session/TerminalSession.kt` | 提供 `openMonitor()`、`closeMonitor()`、`callElevator()`，统一管理对端、等待状态和定时任务。退出监控或切换传输方式时清理旧会话。 |
| `transport/DatagramTransport.kt` | 为会话提供同一组收发方法。接收记录包含来源 IP、来源端口、本机端口和载荷。 |

## 补充抓包进展

`333333.pcapng` 包含地库 1 占线和地库 2 监控，两台门机均只记录入站方向。地库 1 的已知占线包为 `b8 00`、类型 `0x0002`、实际长度 80，但偏移 14 的长度字段为 172。仅对此组合放行并标记占线；地库 2 实际与声明长度均为 80 的正常 `0x0002` 保持普通控制包。占线结束本次等待和周期发送，不向正忙的门机发结束命令。地库 2 的 139 帧 JPEG 已完整解码为 640 × 480。呼梯继续使用单元门机配置。
