# 首页两天天气、菜鸟待取件与卡片重排：开发方案、计划及验收

日期：2026-11-16。开发基线：`9c58c0c`；功能分支：`codex/home-weather-cainiao`。

用户已授权根据实测选择天气来源，完成全部开发、安装验证和复审，不再逐步确认。本文件同时记录最终设计、开发顺序和验收结果，不另设一份内容重复的计划。

## 1. 交付范围与选定方案

- 星期下方显示今天、明天两行天气，各有天气图标、文字和最低～最高温。
- 右侧上排：米家在左，菜鸟在右；下排依次为呼叫电梯、监控、设置。
- 上排两卡同宽同高，下排三卡同宽同高；默认横屏一屏显示，窄屏和大字体允许滚动与纵向展开。
- 菜鸟显示明确的待取件数，可附在途件数；点击打开本机菜鸟。
- 天气采用本机华为系统天气。已证明普通应用能独立托管小组件并隐藏原视图取数，因此不启用第三方 API，不要求用户输入天气凭据。
- 保留当前已完成的门禁、监控、九主题、低亮待机与人脸感知。此次不修改门禁协议、现场网络、物理门锁或电梯行为。

本机系统天气的今天文字表示当前天气，温度为今天的最高/最低范围；明天文字和温度为预报。界面没有把今天的当前天气标为白天预报。

## 4. 小组件接入及生命周期

### 4.1 独立实例与正常授权

- 两个来源分别使用固定 host ID：天气 `0x6EA710`、菜鸟 `0x6CA110`。每次授权根据持久分配 ID 派生独立请求码；即使旧取消结果没有数据，也不能操作后续连接。
- 使用正常 `ACTION_APPWIDGET_BIND` 系统确认，不取得系统签名权限；Manifest 只增加两个指定包的可见性。
- 应用只分配、校验和删除自己宿主的 ID，不接管桌面实例。
- 待授权 ID 在打开系统确认前保存；取消、失败、重新连接时删除。
- 重建时核对提供方与宿主所有权。与 Activity 保存状态匹配的未确认授权继续保留；真正遗留的未绑定 ID 清理。若授权已完成但结果还未交回，可恢复该实例。
- 旧结果、错误请求码和不匹配的返回 ID 不能覆盖新的连接。
- 普通停止、主题重建和销毁页面只移除监听与视图，不删除已连接实例。

使用 Android 官方宿主与正常绑定机制。[Android 小组件宿主](https://developer.android.com/develop/ui/views/appwidgets/host)

### 4.2 隐藏与读取

两个宿主叠放在页面根容器内，不占五卡布局空间。容器完全透明、拒绝触摸和通用输入、阻止后代焦点，并从辅助功能树移除；菜鸟容器还设为 `GONE`，天气则保持测量布局以初始化厂商默认视图。

首次挂载和提供方更新后立即、400ms、2500ms 补读。首页可见时每分钟检查一次；停止后取消队列、停止监听、移除视图，旧视图回调按实例身份丢弃。天气的异步默认视图因此也能被读取。

资源名从提供方视图的资源取得，不把 APK 的整数资源 ID 写死。遍历设节点和单段文字上限。原字段只在内存中解析，持久记录不包含取件码、运单号或地址。

### 4.3 菜鸟刷新

- 首个主动刷新适配只适用于版本名 `8.11.1105` 且版本码 478。
- 必须在首页可见、已连接时发送；普通前台刷新间隔至少 30 分钟。
- 从本应用打开菜鸟返回后可补一次，但距上次请求仍需至少 30 秒。
- 请求时间在发送前保存，重复触发合并；时间回退不导致密集重试。
- 发送显式菜鸟自有广播，同时携带自己的单个 ID 与 ID 数组。不发送受保护的标准广播。
- 未知版本仍可正常监听、读取可识别内容、打开应用；不尝试未验证的主动刷新动作。
- 拒绝或失败只使该卡片降级，不停止接待。

### 4.4 设置与外部应用

“设置 → 外观 → 首页信息”提供天气、菜鸟连接状态，连接/重新连接、断开、打开天气，以及“刷新并返回首页”。没有增加顶层分组和新输入弹窗，也不要求配置城市或密钥。城市和登录沿用来源应用。

首页未连接时点击发起正常授权；已连接后天气区域打开系统天气，菜鸟卡片打开菜鸟。使用标准包启动入口，不把内部 Activity 或不稳定取件链接写进产品。

## 5. 数据解析、日期和缓存

### 5.1 菜鸟

必须同时识别 `tv_pkg_status` 为“待取件”和合法非负 `tv_pkg_num`；当前约束为 0～9999。负数、过大值、未登录、资源缺失、重复字段和其他状态均不可识别。

`tv_pkg_arrive` 仅接受“还有 N 个包裹在路上”的已验证格式，其他说明不保存。明确的“待取件 / 0”可以显示零；仅在途数字或未知空态不能推断为零。

### 5.2 系统天气

- 解析城市、卡片日期、当前天气描述、当日范围和未来行。
- 明确要求摄氏单位；范围须在 -70～60℃，且最低不高于最高。
- 日期使用卡片的“月日 + 星期”，按当前年份附近解析，校验星期且只接受距当前不超过七天的日期；支持跨年。
- 未来行按各自星期匹配基准日后 1～3 天，不用数组位置代替日期；重复或不完整的有效日期不猜测。
- 内部按具体 `LocalDate` 保存，保留来源基准日期；同城同时区、已有预报在当前时间仍可用时，不接受基准日倒退，旧回调不覆盖新预报。未来时间或无对应今日的无效缓存不能阻止来源恢复。显示时按来源时区选择今天和明天。没有对应日就显示“暂无预报”和 `—`。
- 时间、时区或日期变化与返回首页时重选日期，不修改现场系统时间做测试。

### 5.3 保存与新鲜度

数据独立存于解锁后可访问的应用私有 `home-information` 记录，不进入门禁直接启动配置。

- 天气缓存包含城市、时区、具体日期、范围、天气文字与本机读取时间；快递只含两个件数与本机读取时间。
- 相同有效内容重复读取时保留原时间，不延长有效期；若旧时间位于未来，收到合法的当前来源读数后重新记录当前读取时间，以恢复系统时间校正后的显示；不把定时读系统缓存描述为云端更新。
- 天气超过 6 小时或来源基准日早于今天时标“可能未更新”；快递超过 60 分钟标“待更新”。读取出错时，有效旧值同样标记。
- 24 小时后隐藏旧值；未来时间或时区不符的缓存不当作新鲜数据。
- 不可识别不覆盖有效缓存；无缓存时显示连接/打开应用提示。异常不会伪造零件或复制另一天的天气。
- 重新连接或断开时清除对应缓存；两项来源互不影响。

## 6. 实际模块与职责

所有 Kotlin 主路径相对 `app/src/main/kotlin/com/maichimod/prototype/`。

| 模块 | 职责 |
